## 4. 分析与结论
### 本轮目标

v3 暴露问题：负样本信号过度纠正，漏检 3 个真实异常（召回率 66.7%）。v4 采用**路线②"读数与判异常解耦"**：模型只负责读字段，规则引擎做确定性合规判定。

### 做了什么（架构改进，非重新训练）

- 新增 `代码/check_rules.py`：按类别的确定性规则引擎
  - 记账凭证：借贷平衡、凭证字号存在、日期非未来、大写与数字一致
  - 银行回单：付款/收款账号位数（16）、流水号（18 位）、大写与数字一致、日期非未来
  - 差旅报销单：报销日期 ≥ 出差起始、合计 == 明细之和、报销人签名存在
- `test_bills.py` 集成：评估同时报**模型自判**与**规则判定**两套指标
- `gen_report.py` 报告新增规则判定指标

### 效果（在 v3 模型输出上验证）

| 指标 | 模型自判（v3） | 规则判定（v4） |
|---|---|---|
| 异常检测准确率 | 83.3% | **100%** |
| 精确率 | 100% | **100%** |
| 召回率 | 66.7% | **100%** |
| 误报 / 漏检 | 0 / 3 | **0 / 0** |

- 3 个被模型漏掉的异常全部被规则抓住：2 个银行回单账号位数异常（11/13 位）、1 个差旅报销单合计与明细不一致。因为模型**读数正确**（账号、金额都读对了），只是**判断错了**；规则从字段值直接判定，确定性解决。
- 9 个正常样本规则判定 0 误报（账号 16 位、借贷平衡、合计=明细，规则全过）。

### 关键洞察

- 模型"读"的能力已经够好（正常样本字段 0 错误），问题全在"判"。
- 审计异常本质上是**规则**（账号位数/借贷平衡/大写一致/日期/签名），用确定性规则判定：精确率/召回率 100%、可解释、可审计、可复现。
- 训练算力只该花在"读数"上（模型擅长）；"判定"交给规则引擎（免费且 100%）。

### 局限与下一步

- 规则只能判"从文本读出的字段"。**涂改等图像级异常**规则判不了（文本是模型从图上读的，涂改只影响图像本身）——需视觉支线（检测墨迹/修改痕迹）。
- 模型读数在"涂改覆盖金额"的异常样本上仍会错（墨迹糊住数字），这是读数上限，可补更多此类训练数据。
- 可加"规则判定与模型自判不一致 → 人工复核"清单，作为审计 AI 辅助工作流。
