# 训练复盘 — 审计凭证识别 v1→v4

> 2026-08-10 ｜ 项目阶段总结：从首次训练到"模型读数 + 规则判定"架构定型。

## 一、改进方法对比（每次改了什么）

| 版本 | 改进方法 | 层面 | 训练时长 |
|------|---------|------|:--:|
| v1 | 基线：合成数据 + 30% 异常，首次 LoRA 微调 | 数据+训练 | 未记录 |
| v2 | ①涂改墨迹特征化 ②正常样本退化降级 ③异常占比→40% ④评估可量化 | 数据侧 | 34分22秒 |
| v3 | 正常样本加"未发现异常"负样本信号 | 数据侧 | 36分25秒 |
| v4 | 规则引擎：读数（模型）与判异常（规则）解耦 | 架构侧（非重训） | 沿用 v3 |

## 二、指标提升对比

| 指标 | v1 | v2 | v3 | v4 |
|------|:--:|:--:|:--:|:--:|
| 完全一致率 | 未量化(8/15) | 50% | 66.7% | 66.7%(沿v3) |
| 正常样本字段错误 | 多处幻觉 | 0 | 0 | 0 |
| 异常检测准确率 | 未量化 | 83.3% | 83.3% | 100% |
| 精确率 | — | 75% | 100% | 100% |
| 召回率 | 有漏检 | 100% | 66.7% | 100% |
| 误报 FP | 有 | 3 | 0 | 0 |
| 漏检 FN | 有 | 0 | 3 | 0 |
| 最终 loss | 0.1785 | 0.1728 | 0.1747 | — |

## 三、因果链

- v1→v2：数据侧三项改进 → 正常样本不再幻觉、异常全检出，但暴露银行回单误报。
- v2→v3：加"未见异常"负样本信号 → 误报清零，但过度纠正漏检 3 个真实异常。说明模型判定被耦合在文本生成里，改数据只能在精确率/召回率之间摆。
- v3→v4：改架构——模型负责读，规则负责判 → 100%/100%/100%。审计异常本质是规则，规则判定确定性解决。

## 四、每步"值不值"

| 改进 | 值不值 | 理由 |
|------|:--:|------|
| v2 数据增强（涂改特征化/40%异常） | 很值 | 把"读数"从会幻觉拉到 0 错误 |
| v3 负样本信号 | 价值有限 | 只解决具体误报，却牺牲召回——治标不治本 |
| v4 规则引擎 | 最值 | 判定免费且 100%，训练算力只干"读数" |

## 核心结论

> 数据侧改进值得继续投在"读数"上；"判定"永远别让模型做——那是规则的活。

当前架构：模型读数 → 规则判定 →（可选）人工复核不一致项。

## 遗留方向

1. 涂改等图像级异常：规则判不了，需独立视觉检测支线
2. 读数强化："涂改盖金额"等难读样本扩量重训（v5）
3. 真实数据：合成数据覆盖不到的复杂版式，需脱敏真实票据补充
